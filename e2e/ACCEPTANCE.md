## Notes for writing these tests

- Chromium sends a `keepalive` request after its page is gone, and `page.route()` does not reliably see it: sometimes it goes straight through, sometimes it is held and dropped. To keep every save from a closing tab off the server, take the context offline (`context.setOffline(true)`); never rely on a route.
- A name renamed in place shows at once, before the server has it. Wait for the PATCH reply before a reload or an API read.
- Duplicate and paste put the copy one grid step off the original, on top of it. Move the copy (or click off its footprint) before pressing the original again.
- The canvas menu flips to end at the pressed point when it would run off the right edge, which on a phone it usually does for the More button.
- On a phone the zoom controls sit just above the sheet's strip, across most of the width: tap a table clear of them.
- Phones open the editor in View. `waitForEditor` switches to Edit first; `addRoundTable` and `addPreset` click the shape panel on a laptop and go through the Shapes drawer on a phone.
- Touches go through `Touch` in `e2e/canvas.ts`, which sends Chrome's own touch events (CDP `Input.dispatchTouchEvent`), so the app sees real touch pointers, two fingers included. One finger on a table pans unless the table is selected: tap it first to move it.
- The camera reaches the world SVG about 150 ms after a gesture. Read it with `settledCamera`, and turn world points into page points with `worldToClient` or `tableClientCenter`.
- The bottom sheet eases for 200 ms. Wait for it (`sheetAtRest`, which `openProperties` and `lowerSheet` do) before reading where things are, or a touch meant for the sheet lands on the canvas.
- `page.mouse.click` takes no modifiers. Use `clickWith` or `page.keyboard.down('Shift')` around the mouse calls.
- Guests, groups and seats for a test come through the app's routes: `e2e/guest-list.ts` (`apiAddGuests`, `apiCreateGroup`, `apiLinkPartners`, `apiSeatGuests`). `e2e/db.ts` still adds the speed test's 400 guests in one statement, with `name_key` from the app's own `nameKey()`.
- The Guests page is a table at 1440 px and cards below 768 px. `guestEntry` finds a guest's row or card by id, and `guestField` returns the table cell on a laptop or opens the card's Edit dialog on a phone.
- Guest and group edits wait a moment in the row queue before they are sent. Check the server with `expect.poll` on the API, or wait for `expectRowsSaved`, before a reload.
- Every new guest spec presets the author (`presetAuthor`), or the "Who is using this device?" prompt covers the buttons it presses.
- The Guests and Groups pages arrive drawn by the server, and on a laptop look the same once React takes over. Text typed or a file picked before then never reaches React, so `waitForGuestList`, `waitForGroupsPage` and `expectHydrated` (in `e2e/guest-list.ts`) wait until React has attached its props to the field.
- Frame intervals come in whole display refreshes (16.7 ms at 60 Hz), so the speed test counts a frame as slow only when it runs more than 1 ms past its limit: two refreshes (33.4 ms) meet the 33 ms limit.
- The floor plan import tests talk to `e2e/stand-in-anthropic.ts`, which global setup starts on port 4210; `playwright.config.ts` hands the app its address and a dummy key, since the shell may hold its own `ANTHROPIC_BASE_URL`. The stand-in answers by what the prompt holds: a venue named with `REFUSAL_MARKER` gets a refusal, numbered PDF lines get walls by id, anything else the recorded draft. `standInCallsFor(venueName)` lists what the app sent for one test's venue.
- The template editor has its own helpers in `e2e/venues.ts` (`openTemplateEditor`, `templateCamera`, `templateToClient`, `pickTool`, `openTemplateTab`, `startImport`). Points drawn with a draw tool snap to the 1 ft grid, so aim at whole feet (`templateCenterOnGrid`); doors and windows do not snap to the grid.
- A flat SVG line (the scale line, the drawing preview) has a zero-height box, which Playwright counts as hidden. Count it, or check a button that shows with it.
- Two elements carry `data-testid="side-length"` in the template editor: the length field in Properties and the label on the canvas. Scope by `side-length-section` or `template-overlay`.
- Headless Chromium draws a CSS-scaled layer again at full sharpness, so a screenshot alone would not catch a wrapper left scaled after a zoom. `sharpness.spec.ts` therefore also checks that the wrapper has no transform and the SVG holds the camera. A 1 px blur on the canvas fails its pixel comparison (tried by hand).
- A ceremony row is all chairs and in Edit mode every empty chair's + is within 22 px of the pointer, so the first click or tap on a row selects it; the + opens the guest picker only once its row is selected. Pick rows by a chair, not by the "Row 1" label, which is not part of the row's hit area.
- Next.js puts an empty `role="alert"` route announcer on every page, so `getByRole('alert')` alone finds two. Scope it, or use the error's own id (the share password page's is `#share-login-error`).
- A share link's viewer is a second context with no site cookie: `browser.newContext(PHONE or LAPTOP)` from `e2e/canvas.ts`. Share passwords, like the site password, are made up when the test runs.
- The share viewer refetches every 60 seconds. To see that without waiting, install the viewer context's clock before opening the page (`viewer.clock.install()`), which lets time run as usual, then `view.clock.fastForward(SHARE_RECHECK_MS)`. The first server reply stays in the page's script tags, so after the link's switches change, check what the viewer draws (`share-viewer`'s HTML) rather than `page.content()`.
- Note tools arm with a click or tap; the next click on the plan places the note and a drag draws it, on a table too (an arrow then attaches there). On a phone the Shapes drawer closes when a tool is armed. At fit zoom on a phone a touch drag loses its first 8 px, which is a foot or more: drag tables a fixed number of pixels and check against where they land.
